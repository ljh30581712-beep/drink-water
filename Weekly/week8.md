## ② 핵심 지표와 계산 방법

| 지표 | 10/12 값 | 계산 방법 |
|---|---|---|
| **주간 활성 사용자** | **13명** | 최근 7일 안에 `complete`(AI 인증 성공) 이벤트가 1회 이상 있는 외부 사용자의 고유 익명 ID 수 |
| **재방문율** | **21.2%** (7 / 33) | `return`(첫 방문과 다른 날 접속) 이벤트가 기록된 고유 ID ÷ `visit` 고유 ID |
| **핵심 행동 완료율** | **45.5%** (15 / 33) | `complete` 고유 ID ÷ `visit` 고유 ID. 촬영을 시도한 사람 기준(15 / 15)은 100% |

- 퍼널: 방문 33 → 시작 15(이탈 54.5%) → 완료 15(이탈 0%) → 재방문 7(이탈 53.3%). 가장 큰 이탈은 **방문 → 시작**입니다.
- 잠정: 1주차(10/05~10/11) 사용자 30명 중 2주차(10/12 하루)에 다시 온 사용자는 4명(13.3%)입니다. 2주차가 하루뿐이라 과소 추정되므로 대표값으로 쓰지 않습니다.
- 팀·심사용 접속(`internal`) 57건은 집계에서 제외했고, 외부 이벤트는 321건입니다.
- 점검 필요: 10/06은 완료(3)가 시작(2)보다 큰 날로 시작 이벤트 일부가 누락됐을 가능성이 있으며 원인은 확인하지 못했습니다.

## ③ 개선 이력 — 사용자 반응으로 바꾼 3가지

| # | 사용자 반응 | 바꾼 것 | 전 → 후 |
|---|---|---|---|
| 1 | 설문 23명 중 2명이 "설정 화면이 어렵다", 1명이 "몇 분 간격으로 직접 정하게 해달라" | 목표량·근무시간 계산 대신 **몇 분마다 마실지만 입력하는 간단 설정** 추가 | 설정 입력칸 **4개 → 1개**. 설정 불만 2건 → 이후 접수된 설정 불만 0건 |
| 2 | 설문 23건 중 1건 "숫자 입력 때 계속 버벅거린다" | 타이머가 도는 동안 1초마다 화면 전체를 다시 그려 입력칸이 초기화되던 문제를 고침(입력 중에는 다시 그리지 않음) | 입력칸 초기화 **매초 → 0회**. 입력 불만 1건 → 이후 0건 |
| 3 | 팀 테스트에서 AI 판별이 자주 실패(시간초과) | 호출별 제한시간, 늦으면 끊고 대체 모델로 즉시 전환, 함수 제한시간 연장 | 팀 테스트 10회 중 9회 실패(구두, 계측 전) → 외부 AI 오류 **0건**, 시도 15명 중 15명 성공 |

> 정직한 해석: 1~2번의 "이후 0건"은 제보함·설문에 접수된 건수이며 표본이 작아 효과를 단정하지 않습니다. 3번은 고치기 전 수치가 계측 없는 구두 보고라 같은 기준의 비교가 아닙니다. 그 밖에 사용 중 발견해 고친 것: 간격이 5분→30분으로 초기화되던 문제, 로그인 상태에서 지난 기록이 0으로 덮어써지던 문제, 화면이 꺼지면 타이머가 멈추던 문제.

## ④ 배운 것 — 틀렸던 첫 가정 1가지

- **틀린 가정**: "반도체 팹 근로자가 쓰는 서비스다." 마이스터고 학생이라 팹 근로자를 가장 먼저 떠올렸습니다.
- **알게 된 것**: 수원 산업전 인터뷰 6건에서, 팹은 **카메라 사용이 금지**돼 있고 정수기에 카메라를 다는 방법은 비용 부담이 커서 도입이 어렵다는 답을 들었습니다. 방진복을 입지 않는 다른 일터에도 같은 문제(일에 집중하다 물을 못 마심)가 있었습니다.
- **바꾼 것**: 대상을 "카메라를 쓸 수 있는 일하는 사람 전체"로 넓히고, 북극성 지표를 "팹 근로자 사용"에서 "앱이 측정하는 7일 내 인증 성공 외부 사용자"로 바꿨습니다. 팹용 대체 방식은 앞으로의 과제로 남겼고, 사무직 등에서 실제로 효과가 있는지는 아직 검증하지 못한 가설입니다.

## ⑤ 지속 가능성

**월 운영비**
- 현재 Vercel(호스팅)·Firebase(로그인·DB·푸시)·Gemini API(AI 판별)·cron-job.org(알림 스케줄러)를 모두 무료 한도 안에서 쓰고 있어, 월 운영비는 **0원으로 예상**합니다(요금제는 소유자 콘솔에서 확인).
- 사용자가 크게 늘면 AI 호출(Gemini)이 가장 먼저 비용이 됩니다. 사진은 서버에 저장하지 않아 저장 비용은 없습니다.

**이어갈 사람**
- 개발·배포·유지보수는 이준형, 사용자 접촉과 문서는 윤민후가 계속 맡는 것을 계획합니다.
- 코드는 GitHub `main`에 올리면 Vercel이 자동 배포하고, README에 실행·배포 방법이 있어 다른 사람이 이어받을 수 있습니다.

**수익 가설 (미검증)**
- 개인은 무료로 쓰고, 현장 관리자가 팀 단위로 참여율을 보는 기능(팀 대시보드)을 유료로 두는 가설입니다.
- 지금은 핵심 행동 검증이 우선이라 아직 정하지 않았고, 사용자 인터뷰로 지불 의사를 확인하는 것이 첫 단계입니다.

## ⑦ 8주 이후 운영·유지보수 계획

코칭이 끝나도 서비스는 그대로 켜 두고, 아래 방식으로 계속 운영합니다.

| 영역 | 계획 |
|---|---|
| **오류 대응** | 앱 안 💬 제보 버튼으로 들어온 오류·건의는 제보함과 메일로 바로 전달되며, 확인하는 대로 수정합니다. |
| **정기 점검** | 실측 대시보드(`stats.html`)의 AI 오류 기록(종류·상태코드·소요시간)과 퍼널·재방문을 정기적으로 확인하고, 오류가 생기면 원인을 분석해 고칩니다. |
| **배포 방식** | GitHub `main`에 올리면 Vercel이 자동 재배포합니다. 사용자는 새로고침만 하면 최신 버전을 씁니다. |
| **유지 비용** | 현재 월 0원(무료 한도). AI 호출량이 한도를 넘을 때만 비용이 생기며, 그때 사용량에 맞춰 유료 전환을 검토합니다. |
| **홍보·사용자 확대** | 인스타그램 계정 **@water_cycle.ai** 를 개설했고, 제품 홍보용 릴스 게시물을 준비 중입니다. 유입된 사용자의 재방문은 대시보드로 확인합니다. |
| **앱스토어 배포** | 웹 서비스를 안정화한 뒤 **App Store(iOS)·Google Play(Android)** 에 앱으로 배포할 계획입니다. 화면이 꺼진 상태의 알림을 더 안정적으로 보내고, 설치를 쉽게 하기 위한 단계입니다. |

**8주 차에 추가한 것 — 화면이 꺼져도 오는 알림**
- 폰은 화면이 꺼지면 웹페이지를 멈춰 알람이 울리지 않는 문제가 있었습니다.
- 타이머를 "끝나는 시각" 기준으로 바꾸고, 알림을 켠 기기는 서버(`api/push.js`)에 알람 시각을 예약해 두면 1분마다 도는 스케줄러가 Firebase Cloud Messaging으로 푸시를 보냅니다. 인증 전까지 1분마다 최대 5회 다시 알립니다.
- 아이폰은 "홈 화면에 추가"한 앱에서만 받을 수 있어, 앱 안에 기기별 설정 안내 창을 넣었습니다.
