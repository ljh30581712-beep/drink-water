## ① MVP 범위표

> **핵심 행동**: 산업 현장 근로자가 알람이 울리면 물 마시는 모습을 촬영하고, AI가 실제로 마셨는지 확인해 성공하면 알람이 꺼진다.

이번에 만들 것(핵심)은 알람 타이머, 카메라 촬영, AI(Gemini Vision) 판별, 판별 성공 시 알람 해제, 실패 시 재촬영이다. 이 다섯 가지만 매끄럽게 작동하면 핵심 행동은 완성된다.

이미 만들었지만 핵심은 아닌 것으로는 로그인·클라우드 저장, 8개 언어 지원, 알람음 3종, 진동 on/off, 화면 플래시, FAQ, 하루 시작 시간 설정이 있다. 이 기능들이 없어도 핵심 행동은 그대로 작동하기 때문에, 엄밀히 말하면 MVP 범위 밖의 부가기능이다.

이번에 안 만들 것(지운 목록)은 관리자 대시보드, QR 출입 태깅, 카메라 반입이 제한되는 현장을 위한 대체 인증(센서·사원증), 이중 알람, 교대 패턴 자동 조정, 데이터 연계 분석, 히트맵 시각화다.

**이번 주 판단**: 저희는 서비스의 대상을 반도체 팹 근로자에서 모든 산업 현장 근로자로 넓히기로 결정했다. 반도체 산업 전시회 현장 인터뷰를 통해, 방진복을 입지 않는 일반 산업 근로자도 물을 충분히 마시지 못한다는 동일한 문제를 겪고 있음을 확인했다. 오히려 반도체 팹 클린룸은 카메라 반입이 원천 금지되어 있고 방진복 장갑 때문에 터치 조작도 어려워, 저희가 처음 구상한 AI 사진 인증 방식을 그 현장에는 적용하기 어렵다는 현실적인 제약도 함께 발견했다. 이에 따라 카메라 사용에 제약이 없는 산업 현장 전반으로 타겟을 넓히고, 반도체 클린룸 같은 특수 환경에 대한 대응은 별도의 향후 과제로 분리했다.

## ② 아키텍처 1장

사용자 브라우저는 알람과 촬영 UI를 담당하며, 촬영한 사진을 Vercel 서버리스 함수로 전송한다. 이 서버 함수는 API 키를 안전하게 보관하고 있어 클라이언트에는 절대 노출되지 않으며, 이미지와 프롬프트를 Google Gemini API로 전달한다. Gemini는 음수 여부를 판별하고 그 이유를 생성해 판별 결과(JSON)를 다시 브라우저로 반환한다. 로그인을 선택한 사용자에 한해서는 브라우저가 Firebase Auth와 Firestore에도 연결되어 기록을 저장하지만, 로그인하지 않아도 전체 기능을 이용할 수 있다.

```
[사용자 브라우저]  --사진(JPEG)-->  [Vercel 서버리스 함수]  --이미지+프롬프트-->  [Google Gemini API]
   (알람, 촬영 UI)                (API 키 보관,                            (음수 여부 판별,
                                   클라이언트에 노출 안 됨)                  판별 이유 생성)
        ↑                                                                    │
        └──────────────────────── 판별 결과(JSON) 반환 ─────────────────────────┘

[사용자 브라우저]  --(로그인 시, 선택)-->  [Firebase Auth / Firestore]
                                            기록 저장 · 로그인 없어도 전체 기능 이용 가능
```

## ③ AI 사용 내역 · 라이선스

핵심 AI 모델은 Google Gemini의 `gemini-3.5-flash`(주 모델)와 `gemini-3.5-flash-lite`(대체 모델)이며, 둘 다 Vision(이미지 이해) API로 사진 속 음수 행동을 판별하는 데 사용된다. 개발 과정에서는 Claude(Anthropic)로 코드 작성과 디버깅을, Gemini로 기획 아이디어 구상을, HyperCLOVA X로 문서 작문을, ChatGPT로 팀 로고 이미지 생성을 보조로 활용했다.

프로젝트 자체 소스코드는 MIT License로 GitHub에 공개되어 있다. 로고는 ChatGPT로 생성했고, 폰트는 상업적 이용이 가능한 무료 라이선스인 Noto Sans 계열을 사용했다. 개인정보 측면에서는 촬영 이미지를 AI 판별 1회 용도로만 사용한 뒤 즉시 폐기하며 서버나 데이터베이스에 저장하지 않고, 실명이 포함되어 있던 인터뷰 원본 기록도 GitHub 공개 전 전원 익명 처리를 완료했다.

## ④ 보안 점검

가장 민감한 정보인 `GEMINI_API_KEY`는 코드 어디에도 하드코딩되어 있지 않다. `process.env.GEMINI_API_KEY` 형태로 Vercel 서버의 환경변수에서만 불러오도록 되어 있어, 소스코드나 GitHub 저장소 어디를 봐도 실제 키 값은 노출되지 않는다.

다만 index.html 안에는 Firebase 설정값(apiKey 포함)이 그대로 보이는데, 이는 실제 문제가 아니다. Firebase의 클라이언트용 apiKey는 원래 브라우저에 공개되도록 설계된 값이며, 실제 접근 제어는 이 키가 아니라 Firestore 보안 규칙이 담당하기 때문이다.

마지막으로 인터뷰 원본 기록에 실명이 남아있는지 확인한 결과, GitHub에 공개하기 전 응답자 전원을 성+OO 형태로 익명 처리했고, 사전 동의를 받지 못한 응답자는 "응답자 C"처럼 코드명으로 처리해 실명이 남아있지 않다.
